# Plota capability question — draft, not sent

Subject: Application-form fields, document data and parent links in our API plan

Hi Plota team,

We use your API to identify significant commercial developments. We want to show the proposed
operator, existing/proposed use classes, commercial floor area and site area, with evidence.
Our own reader often cannot retrieve council application forms, so we want to understand what
you can already supply before building more document collectors.

Could you clarify:

1. Can API responses include application-form fields, extracted document text, document titles/
   categories or direct document URLs? Please distinguish content you supply from council links.
2. What does `floorspace_sqm` mean: existing, proposed, gained, lost or net change? Is it commercial
   area or all uses, which measurement basis is used, and is the original source available?
3. Do you hold separate existing/proposed use classes and site area, with units and source dates?
   How do you handle conflicting figures or amendments to an earlier permission?
4. What coverage do these fields have by council and application type? A small representative
   sample would help us distinguish available fields from reliably populated ones.
5. Can parent references/IDs or related-application IDs be included in normal discovery/backfill
   responses? Does requesting them consume additional allowance, and what additional requests
   are needed to obtain an older original or the complete family?
6. Which capabilities are included in our current plan, and what would an add-on or bulk export
   cost? Please explain how each option affects our request allowance.

We are asking for capability and pricing information only; please do not enable paid additions
or run a chargeable export at this stage.

Thanks,
Tom
